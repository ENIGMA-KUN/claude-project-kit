# Knowledge graph schema

`knowledge/` is a directory of Markdown files that together form a graph. It follows the Open Knowledge Format idea (one concept per file, YAML frontmatter with a required `type`, `index.md` and `log.md` reserved) and adds typed relations, status and review dates so the graph can be maintained by loops instead of growing forever.

Files whose name starts with `_` (like this one) are documentation or generated output, not nodes. `index.md` and `_graph.json` are regenerated by `python .claude/kit/kg.py build`.

## Node types and folders

| type | folder | Holds | Typical source |
|------|--------|-------|----------------|
| `architecture` | `architecture/` | A module, layer or component: responsibility, boundaries, key paths, gotchas | `/kit-init` scan, design work |
| `decision` | `decisions/` | A choice and why: context, decision, rejected alternatives, consequences | ADRs, PR discussions, the user |
| `lesson` | `lessons/` | A mistake or trap and the rule that prevents it | corrections, failed attempts, `/learn` |
| `solution` | `solutions/` | A solved non-trivial problem with the full fix | debugging sessions |
| `concept` | `concepts/` | A domain term or metric and what it means here | the user, docs, data dictionaries |
| `procedure` | `procedures/` | A repeatable runbook; a candidate to become a skill | repeated multi-step work |
| `proposal` | `_inbox/` | A pending change to rules, CLAUDE.md, skills, hooks or the graph | `/reflect`, `/curate` |

Other `type` values are allowed (for example `dataset`, `api`, `metric`) and are indexed like any node; `validate` only warns about them.

## Frontmatter

```yaml
---
type: lesson                      # required
title: "Use uv, not pip"          # short noun phrase
description: "pip installs into the global interpreter here; uv manages the project venv."
tags: [python, tooling]
status: active                    # candidate | active | superseded | archived
confidence: high                  # low | medium | high
source: "correction, session 2026-11-21"   # provenance: session, PR, file, URL
created: 2026-11-21
updated: 2026-11-21
review_by: 2027-02-19             # after this date the node shows as stale
rule: "Run uv sync and uv run; never call pip directly."   # lessons only
trigger: [pip install, ModuleNotFoundError, site-packages]  # lessons: text seen when it recurs
severity: medium                  # lessons: low | medium | high | critical
paths: [pyproject.toml, "src/**"] # files this node is about; used for drift detection
relations:
  depends_on: [architecture/build-system]
  related: [solutions/venv-mismatch]
---
```

Proposals add `target` (file to change), `control` (`knowledge`, `rule`, `claude-md`, `skill`, `hook`, `test`, `lint`), `scope` (`project` or `kit`), `times_proposed` and `evidence`, and use the statuses `proposed | accepted | rejected | deferred`.

The parser supports this YAML subset: `key: value`, inline lists `[a, b]`, block lists with `- item`, and one level of nested maps (used by `relations`). Quote values that contain `#` or `:`.

## Relations

| relation | meaning | strong |
|----------|---------|--------|
| `depends_on` | this node only makes sense with the target | yes |
| `part_of` | this node is a piece of the target | yes |
| `implements` | this node carries out the target decision | yes |
| `supersedes` / `superseded_by` | this node replaces / was replaced by the target | yes |
| `related` | worth reading together | no |
| `contradicts` | the two disagree; one must win | no |
| `caused_by` / `fixes` | a lesson's root cause / a solution's problem | no |
| `example_of` | a concrete case of a general node | no |

A strong relation to a missing node is a validation error. Markdown links between nodes become untyped `links` edges.

## Status lifecycle

```
candidate --(user approves)--> active --(replaced)--> superseded
     |                           |
     +--(rejected)--> archived <-+--(no longer true)
```

Only `active` nodes are served to sessions by the retrieval hook. Candidates and proposals wait for a human decision.

## Writing good nodes

- Description first: it is what the index, the retrieval hook and other agents see.
- A lesson separates the reusable principle (`rule`) from the concrete incident (body). Over-specific lessons never match again.
- Prefer the strongest control. If a lint rule, type, test or hook can catch the mistake, propose that and keep the lesson as the explanation.
- Set `paths` when a node is about specific code. `validate` reports drift when those paths disappear.
